# 多模态生成工作台 —— 前端实现详解

本文档逐项讲解前端的工程结构、数据流、SSE 订阅、三种模态的交互与渲染逻辑，及关键代码细节。

- 状态：React 内置 Hooks（`useState` / `useRef` / `useCallback`），未引入额外状态库

## 4. 类型定义 types.ts

文件位置：[types.ts](frontend/src/types.ts)

```ts
export type Mode = 'text' | 'image' | 'image_to_text'

export type TaskStatus = 'pending' | 'running' | 'done' | 'error'

export interface TaskRecord {
  id: number
  mode: Mode
  prompt: string
  status: TaskStatus
  result_text?: string | null
  result_url?: string | null
  error?: string | null
  created_at: string
}
```

说明：

- `Mode` 三元组与后端 `mode` 字段一一对应。
- `TaskRecord` 与后端的 `TaskResponse` 字段对齐，注意后端返回的是**蛇形命名**（`result_text`、`result_url`），前端类型里照搬保持一一对应。
- 可选字段（`result_text` 等）标为 `?` 且允许 `null`，因为任务未完成时这些字段为空。

## 5. 接口与 SSE 封装 api.ts（核心）

文件位置：[api.ts](frontend/src/api.ts)

### 5.1 提交生成任务 generate

```ts
export async function generate(
  mode: Mode,
  prompt: string,
  imageBase64?: string,
): Promise<TaskRecord> {
  const res = await fetch('/api/generate', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ mode, prompt, image_base64: imageBase64 }),
  })
  if (!res.ok) {
    const err = await res.json().catch(() => null)
    throw new Error(err?.detail || `请求失败: ${res.status}`)
  }
  return res.json()
}
```

- 直接返回 `TaskRecord`，其中就含有后端下发的 `task_id`（即 `id` 字段）。
- 错误处理：后端校验失败会返回 `{ "detail": "..." }`，这里优先取 `detail` 作为报错文案。

### 5.2 查询历史 listTasks

```ts
export async function listTasks(): Promise<TaskRecord[]> {
  const res = await fetch('/api/tasks')
  return res.json()
}
```

### 5.3 SSE 订阅 streamTask

```ts
export type StreamEvent =
  | { type: 'status'; status: string }
  | { type: 'delta'; text: string }
  | { type: 'done'; result_text?: string; result_url?: string }
  | { type: 'error'; error?: string }

export function streamTask(taskId: number, onEvent: (e: StreamEvent) => void): () => void {
  const es = new EventSource(`/api/tasks/${taskId}/stream`)
  es.onmessage = (msg) => {
    try {
      onEvent(JSON.parse(msg.data) as StreamEvent)
    } catch {
      // 忽略无法解析的消息
    }
  }
  return () => es.close()
}
```

关键设计：

- **用浏览器原生 `EventSource`**（而非 fetch 手动解析），自动处理 SSE 的 `text/event-stream` 协议与重连。
- **`StreamEvent` 是可辨识联合类型**：四种事件各有独立字段，配合 `switch(event.type)` 可让 TypeScript 做类型收窄，避免手写 any。
- **返回清理函数 `() => es.close()`**：调用方拿到后存起来，在组件卸载或发起新任务前关闭旧连接，防止连接泄漏。
- `msg.data` 是后端 `data: {...}` 的 JSON 文本，`JSON.parse` 成对象；`try/catch` 吞掉心跳行（`:` 开头的注释不会被 `onmessage` 触发，但稳妥起见忽略解析异常）。

## 6. 工作台主逻辑 Workbench.tsx（核心）

文件位置：[Workbench.tsx](frontend/src/pages/Workbench.tsx)

这是前端唯一的「有状态 + 有副作用」的组件，负责把「输入 → 生成 → 订阅 → 渲染 → 刷新历史」串起来。

### 6.1 状态定义

```tsx
interface ActiveTask {
  taskId: number
  status: string
  resultText: string
  resultUrl: string
  error: string
  done: boolean
}

const [mode, setMode] = useState<Mode>('text')
const [prompt, setPrompt] = useState('')
const [imageBase64, setImageBase64] = useState<string | null>(null)
const [active, setActive] = useState<ActiveTask | null>(null)
const [history, setHistory] = useState<TaskRecord[]>([])
const stopRef = useRef<(() => void) | null>(null)
```

两套数据模型的分工：

| 状态 | 类型 | 用途 |
|------|------|------|
| `mode` / `prompt` / `imageBase64` | 基本类型 | 用户输入 |
| `active` | `ActiveTask` | 当前生成中的任务（前端自己维护的运行时状态） |
| `history` | `TaskRecord[]` | 后端历史列表 |

注意 `ActiveTask` 是**前端私有类型**（字段是驼峰 `resultText`），区别于后端的 `TaskRecord`（蛇形 `result_text`）。因为 `active` 需要被 `setActive` 频繁局部更新（流式追加文本），用一个扁平可变结构更顺手。

### 6.2 历史加载

```tsx
const refreshHistory = useCallback(async () => {
  const tasks = await listTasks()
  setHistory(tasks)
}, [])

useEffect(() => {
  refreshHistory()
}, [refreshHistory])
```

组件挂载时拉一次历史。`useCallback` 固定引用，避免 `useEffect` 重复触发。

### 6.3 SSE 连接清理

```tsx
useEffect(() => {
  return () => stopRef.current?.()   // 组件卸载时关闭未完成的 SSE
}, [])
```

### 6.4 生成主流程 onGenerate（核心）

```tsx
const onGenerate = async () => {
  if (!prompt.trim()) return
  if (mode === 'image_to_text' && !imageBase64) return   // 前置校验

  stopRef.current?.()   // 发起新任务前先关闭旧 SSE

  try {
    const task = await generate(mode, prompt, imageBase64 ?? undefined)
    setActive({ taskId: task.id, status: 'pending', resultText: '', resultUrl: '', error: '', done: false })

    const stop = streamTask(task.id, (event) => {
      setActive((prev) => {
        if (!prev || prev.taskId !== task.id) return prev   // 忽略迟到事件
        switch (event.type) {
          case 'status':
            return { ...prev, status: event.status }
          case 'delta':
            return { ...prev, resultText: prev.resultText + event.text }   // 流式追加
          case 'done':
            return { ...prev, status: 'done', resultText: event.result_text ?? prev.resultText,
                     resultUrl: event.result_url ?? prev.resultUrl, done: true }
          case 'error':
            return { ...prev, status: 'error', error: event.error ?? '生成失败', done: true }
          default:
            return prev
        }
      })
    })
    stopRef.current = stop
  } catch (err) {
    setActive({ taskId: 0, status: 'error', resultText: '', resultUrl: '', error: err.message, done: true })
  }
}
```

逐步拆解：

1. **前置校验**：`prompt` 为空、或图片理解模式无图时直接 return（前端拦截，后端仍会再校验一次）。
2. **先关旧连接**：`stopRef.current?.()` 保证同一时刻只有一路 SSE。
3. **提交拿 task_id**：`await generate(...)` 返回后立刻初始化 `active` 为 `pending`。
4. **订阅 SSE**：`streamTask(task.id, callback)` 的 callback 用 `setActive(prev => ...)` **函数式更新**，保证事件乱序/并发下基于最新 state 计算。
5. **事件映射**：
   - `delta` → 文本**追加**（流式打字效果）。
   - `done` → 用 `??` 只在后端没给完整值时保留前端累积值（文生文场景后端会回传完整 `result_text`，直接覆盖）。
   - `error` → 记录失败原因。
6. **subscribe 后立即把 `stop` 存到 `stopRef`**，供下次或卸载时关闭。
7. **try/catch 兜住 submit 阶段的异常**（如网络错误、后端 400），直接落一个 error 状态。

### 6.5 结果落定后刷新历史

```tsx
useEffect(() => {
  if (active?.done) {
    refreshHistory()
  }
}, [active?.done, refreshHistory])
```

任务终态（done 或 error）后自动刷新历史列表，让右侧实时出现新记录。

### 6.6 历史项点击回看

```tsx
const onSelectHistory = (item: TaskRecord) => {
  setActive({
    taskId: item.id,
    status: item.status,
    resultText: item.result_text ?? '',
    resultUrl: item.result_url ?? '',
    error: item.error ?? '',
    done: item.status === 'done' || item.status === 'error',
  })
  setMode(item.mode)
}
```

把历史记录「回填」进 `active`，结果区即可复用同一套渲染逻辑展示历史内容。

### 7.2 图片上传转 base64（关键）

```tsx
const handleUploadChange = ({ fileList: list }) => {
  const latest = list.slice(-1)          // 只保留最后一张
  setFileList(latest)
  const file = latest[0]
  if (file && file.originFileObj) {
    const reader = new FileReader()
    reader.onload = () => onImageBase64Change(reader.result as string)
    reader.readAsDataURL(file.originFileObj)   // 转 data URL
  }
}
```

```tsx
<Upload.Dragger
  maxCount={1}
  fileList={fileList}
  beforeUpload={() => false}   // 关键：阻止默认上传行为
  onChange={handleUploadChange}
  listType="picture"
>
```

- **`beforeUpload={() => false}`**：告诉 AntD 不要真正发起上传请求，只做 UI 层面收集文件。
- 手动用 `FileReader.readAsDataURL` 把文件二进制转成 base64 data URL，交给父组件存储。
- `list.slice(-1)` + `maxCount={1}` 保证只保留最近一张。
- 该组件仅在 `mode === 'image_to_text'` 时渲染上传区。

这样设计避免了文件传输走 multipart，统一走 base64 JSON，与后端 `_save_base64_image` 一一呼应。

## 8. 结果区 ResultPanel.tsx

文件位置：[ResultPanel.tsx](frontend/src/components/ResultPanel.tsx)

按优先级分支渲染，逻辑清晰：

```
无任务        → Empty（空态提示）
任务失败      → Alert（错误展示）
图片模式      → 有 resultUrl 显示 <Image>；否则 Spin 加载提示
文本类模式    → 有 resultText 显示文本；否则 Spin 加载提示
```

关键片段：

```tsx
if (mode === 'image') {
  if (active.resultUrl) {
    return <Image src={active.resultUrl} alt="生成图片" />   // AntD 图片，自带放大预览
  }
  if (loading) {
    return <div className="loading-box"><Spin /><span>图片生成中，通常需要数十秒...</span></div>
  }
  return <Empty description="暂无图片" />
}

if (active.resultText) {
  return <Typography.Paragraph className="result-text">{active.resultText}</Typography.Paragraph>
}
```

- 图片用 AntD 的 `<Image>`（自带点击放大）；`resultUrl` 形如 `/outputs/xxx.png`，由 Vite 代理转给后端静态目录。
- 文本用 `Typography.Paragraph` + `result-text` 类（`white-space: pre-wrap`），保留换行、自动断行。
- `resultText` 在流式过程中被不断追加，这里会随 `active` 更新实时重渲染，形成打字机效果。

## 11. 与后端的接口/数据对应关系

| 前端 | 后端 | 说明 |
|------|------|------|
| `generate(mode, prompt, imageBase64)` | `POST /api/generate` | `imageBase64` → `image_base64` |
| `listTasks()` | `GET /api/tasks` | 历史列表 |
| `streamTask(taskId)` | `GET /api/tasks/{id}/stream` | SSE 订阅 |
| `StreamEvent` 四种类型 | 后端 `_sse` 推送的 `type` | 完全一致 |
| `TaskRecord`（蛇形字段） | `TaskResponse` | 一一对应 |
| `<Image src="/outputs/xx.png">` | `StaticFiles` 挂载 `/outputs` | 图片访问 |

## 12. 关键设计点总结

1. **无内联样式**：所有样式集中在 `styles.css` + className，主题统一在 `ConfigProvider` 配置，契合「白底浅蓝」的视觉规范。

2. **类型驱动**：`StreamEvent` 用可辨识联合类型，`TaskRecord` 与后端字段精确对齐，编译期即可拦截字段拼写错误。

3. **SSE 生命周期管理**：`streamTask` 返回清理函数，配合 `stopRef` 在「新任务前 / 组件卸载时」主动关闭，避免连接泄漏与串台。

4. **函数式 setState**：SSE 回调里一律 `setActive(prev => ...)`，避免事件异步到达导致的状态覆盖（尤其是流式 `delta` 连续追加场景）。

5. **单一数据源复用**：历史记录点击回看时，把 `TaskRecord` 转成 `ActiveTask` 复用同一套 `ResultPanel`，不额外写一套展示逻辑。
